### Epic

Vivi.lv Website Functionality and Ticket Purchasing

Provide passengers with access to train information, ticket purchasing, and passenger services through the Vivi.lv website.


### User Stories and Acceptance Criteria

User Story 1 – Main Navigation

User Story
As a website visitor, I want to navigate the website using the main navigation menu so that I can easily find the information I need.

Acceptance Criteria
1. The main navigation menu is displayed on the relevant public pages.
2. Each navigation menu item has a clear and understandable label.
3. Selecting a navigation menu item takes the user to the corresponding page or section.
4. The current page or section is identifiable in the navigation menu when this functionality is provided.
5. The navigation menu remains usable without overlapping or obscuring the main page content.


User Story 2 – Viewing Notifications and Announcements

User Story
As a website visitor, I want to view important notifications and announcements so that I can stay informed about relevant updates to train services.

Acceptance Criteria
1. Notifications or announcements are displayed in the designated section of the website when available.
2. Each notification displays its available title and content.
3. Notification content is readable and does not overlap other page elements.
4. If a notification can be opened for more information, selecting it displays the corresponding content.
5. Users can access notifications without signing in if they are intended for public viewing.


User Story 3 – Viewing News Articles

User Story
As a website visitor, I want to browse news articles and read their full content so that I can stay informed about news and updates published by Vivi.

Acceptance Criteria
1. The website displays available news articles in the designated news section.
2. Each news article displays its available title and publication information.
3. Selecting a news article opens the corresponding article page or detailed view.
4. The article page displays the available article content correctly.
5. The user can return to the news list using the available navigation options.
6. News article content is displayed correctly without overlapping other page elements.
7. News article links open the corresponding content without displaying an error page when the article is available.

User Story 4 – Viewing Route Changes on the Map

User Story
As a website visitor, I want to view information about route changes on the map so that I can understand how they may affect my journey.

Acceptance Criteria
1. Users can access the map and map section that displays route change information.
2. Available route changes are indicated in the associated information section.
3. Route change information identifies the affected route when this information is provided.
4. Route change information is readable and does not obscure essential map controls.


User Story 5 – Using the Interactive Map

User Story
As a website visitor, I want to use the interactive map to explore available railway routes and related travel information so that I can better understand the railway network.

Acceptance Criteria
1. Users can open and view the interactive map.
2. The map displays the railway routes and other map information available in the interface.
3. Users can move around the map using the supported map controls or gestures.
4. Users can zoom in and out of the map when these controls are available.
5. Selecting an interactive map element displays the corresponding information when this functionality is supported.
6. Map controls remain usable and do not unintentionally block the relevant map content.


User Story 6 – Viewing Contact Information

User Story
As a website visitor, I want to find Vivi’s contact information so that I can contact the appropriate service when I need assistance.

Acceptance Criteria
1. Users can find the contact information through the available website navigation.
2. The contact section displays the contact details published by Vivi.
3. Displayed telephone numbers and email addresses are readable and clearly identifiable.
4. Selecting a clickable telephone number initiates a call on supported devices
5. Selecting a clickable email address opens the default email application.

User Story 7 – Accessibility Settings

User Story
As a website visitor, I want to use the available accessibility settings so that I can adjust the website interface to better suit my needs.

Acceptance Criteria
1. Users can locate the accessibility settings if they are provided on the website.
2. Users can activate an available accessibility option.
3. The selected accessibility option produces the expected visible changes in the relevant website interface elements.
4. Users can change or reset the selected option using the available controls.


US8 – Train Search

User Story
As a website visitor, I want to search for trains by selecting departure and destination stations and a travel date so that I can find a suitable train for my journey.

Acceptance Criteria
1. The user can select a departure station from the available station options.
2. The user can select a destination station from the available station options.
3. The user can select a travel date using the available date selection control.
4. The website displays train search results matching the selected departure station, destination station, and travel date when matching services are available.
5. The website displays an appropriate validation message when required search fields are left incomplete.
6. The user can change the search criteria and perform a new search.
7. The user can sort the search results using the available sorting options.
8. The displayed search results reflect the selected sorting option.
9. The user can open the detailed information for a selected train from the search results.
10. The displayed train details correspond to the selected search result.
11. If no trains match the selected search criteria, the website communicates that no results are available without displaying misleading results.
12. Search results and validation messages are displayed clearly and remain readable.


US9 – Ticket Selection and Payment

User Story
As a passenger, I want to select an available ticket type and payment method so that I can proceed with purchasing a ticket for my journey.

Acceptance Criteria
1. The user can access the ticket selection page through the available ticket selection or cart control.
2. The website displays the ticket types available for selection.
3. The user can select an available ticket type.
4. The website displays the ticket options corresponding to the selected ticket type.
5. The user can proceed through the available ticket purchase flow as a guest or as an authenticated user, where supported.
6. The website provides the option to register before completing the purchase, where this option is available.
7. The website displays the available payment methods at the appropriate stage of the purchase process.
8. The user can select an available payment method.
9. The selected ticket type and payment method remain correctly represented in the purchase flow as the user proceeds through the available steps.
10. The website displays the relevant information required for the user to review the ticket selection before proceeding, where such a review step is provided.
11. If a required selection is missing, the website prevents progression where necessary and displays an appropriate validation message.
12. The user receives clear feedback when an action is completed or when the purchase process cannot proceed.
13. The purchase flow does not display a successful purchase confirmation unless the purchase has been completed successfully.


US10 – Account and Purchase History Management

User Story
As a registered user, I want to access and manage my account information, view my purchased tickets, and review my purchase history so that I can manage my travel-related information in one place.

Acceptance Criteria
1. The user can create a new account using the registration options provided by the website.
2. The user can sign in using a registered email address and password.
3. After successful authentication, the user can access the My Account area.
4. The My Account area displays the account sections and options available to the authenticated user.
5. The user can view their purchased tickets in the My Tickets section when ticket records are available.
6. The user can filter purchased tickets by ticket type when the filtering functionality is provided.
7. The user can access the ticket purchase process from the My Tickets section using the available controls.
8. The user can view their profile information and registered contact details.
9. The user can manage discount card information using the available account controls.
10. The user can add or manage an email address for ticket delivery where this functionality is available.
11. The user can access the password change functionality from the appropriate account section.
12. The password change form provides fields for the current password, new password, and confirmation of the new password.
13. The website provides appropriate validation feedback when required password fields are incomplete or the new password and its confirmation do not match.
14. The user can view their purchase history when purchase records are available.
15. The purchase history displays the available purchase details, such as the ticket number, train number, route, ticket type, payment date, order number, and purchase price.
16. The user can initiate a repeat purchase from a previous purchase when this functionality is available.
17. The user can access the account deletion option where it is provided.
18. The website requires the user to follow the available account deletion confirmation or verification steps before completing the deletion.
19. The website displays clear feedback indicating whether an account-related action has been completed successfully or could not be completed.
20. The website displays the account information, purchased tickets, and purchase history associated with the currently authenticated user.

US11 – Notification and Favourite Route Management

User Story
As a registered user, I want to manage my notification preferences and save or remove favourite routes so that I can keep track of relevant travel information and quickly access routes I use frequently.

Acceptance Criteria
1. The user can access notification preferences from the My Account section.
2. The website displays the available notification preference options.
3. The user can enable or disable an available news notification preference.
4. The user can subscribe to route-specific notifications when this functionality is provided.
5. The website provides clear feedback when a notification preference is changed.
6. The user can save a selected route as a favourite route when authenticated and when the functionality is available.
7. The website displays saved favourite routes in the Favourite Routes section of the authenticated user’s account.
8. The user can add a favourite route using the available controls.
9. The user can remove a saved favourite route using the available controls.
10. After a route is removed, it no longer appears in the Saved Routes list.
11. Changes to favourite routes are reflected in the Saved Routes list after the action is completed.
12. The website displays an appropriate empty state when no favourite routes have been saved.
13. The notification preference and favourite route controls have clear labels, and the website displays understandable feedback when the user changes a notification preference or adds or removes a favourite route.


US12 – Payment Card Management

User Story
As a registered user, I want to view and manage saved payment cards so that I can use the available payment options when purchasing tickets.

Acceptance Criteria
1. The user can access the payment card management section from the My Account area.
2. The website displays the saved payment cards associated with the authenticated user’s account when saved cards are available.
3. The user can identify the displayed saved cards using the information made available by the interface.
4. The website provides an option to add a new payment card when this functionality is available.
5. Selecting the add-card option opens the appropriate card entry form or redirects the user to the relevant payment service.
6. The card entry interface clearly identifies the fields required to add a payment card.
7. The website provides appropriate validation feedback when required card details are missing or invalid, where validation is handled by the visible interface.
8. The user receives clear feedback when the card addition process succeeds or cannot be completed.
9. Sensitive payment card information is not unnecessarily exposed in the visible interface.
10. The payment card management section displays an appropriate empty state when no saved cards are available.


US13 – Security and Data Protection Through the UI

User Story
As a website user, I want the website to protect access to account-related information and handle sensitive input appropriately so that my personal and travel-related information is not exposed through unauthorised UI access.

Acceptance Criteria
1. A user who is not authenticated is prompted to sign in when attempting to access a protected account page or function.
2. After successful authentication, the user can access the protected account pages and functions available to the authenticated account.
3. The website provides a sign-out option when the user is authenticated.
4. After signing out, the website displays the unauthenticated state, such as a sign-in option instead of authenticated account controls.
5. After signing out, attempting to reopen a protected account page through the available browser navigation does not provide continued access to protected account content without the required authentication.
6. Password input fields conceal entered characters by default, unless the interface explicitly provides a show-password control.
7. The website displays appropriate validation or error messages when authentication input is missing or invalid.
8. After repeated unsuccessful sign-in attempts, the website displays appropriate feedback and does not indicate that authentication was successful.
9. When invalid input is entered into an in-scope form, the website displays appropriate validation feedback and the visible interface remains functional.
10. The website does not display passwords or other sensitive information unnecessarily in visible page content or confirmation messages.
11. Account-related information displayed after authentication corresponds to the account currently in use.
12. Account deletion requires the available confirmation or verification steps and is not triggered accidentally by opening the deletion option.
13. Authentication and security-related error messages provide understandable guidance without revealing passwords or unnecessary sensitive account information.
14. Security checks are limited to authorised, non-invasive verification through the user interface; backend security, infrastructure security, penetration testing, and automated attack testing are excluded from this User Story’s scope.
